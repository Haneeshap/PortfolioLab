# M38-M40 implementation plan and verification

## Architecture audit and plan

The Go simulator owns 25 fictional INR live prices, updated every five seconds, with no OHLCV endpoint or durable daily history. M29 persists a 24-hour live observation buffer for intelligence; that is not OHLCV and has no volume. Existing portfolio snapshots are portfolio valuations, not asset OHLCV. Spring holdings expose historical portfolio-currency costs and catalog prices; live prices come through MarketService. Assets have no sector classification. The Next application already has Recharts, AppShell navigation and a single PortfolioChat. The sibling AI service has MCP stdio tools, deterministic order intelligence and a separate Ollama explanation path.

1. M38: deterministic versioned UTC daily fixtures generated by Go; bounded on-demand ingestion into a uniquely indexed PostgreSQL OHLCV table through V21; backend indicator calculations; integrated research chart/replay using Recharts and local playback state.
2. M39: read-only scoped exposure/scenario service using existing holdings and current-price infrastructure; reuse indicator/history mathematics for supported risk metrics; integrated portfolio Risk Lab. Missing prices/history/FX and absent sectors must remain explicit.
3. M40: scoped read-only MCP research/risk tools, deterministic numerical explanations and explicit research context in the existing Ask AI. Keep order intelligence first in routing and avoid live-model dependencies in tests.
4. Run targeted checks per milestone, then regression tests/type checks/builds and document actual evidence. No commits or pushes.

History is explicitly generated fictional fixture data and is independent of live price trajectories. Replay never changes Go state, OMS records or portfolio data. Risk calculations never ingest history or mutate tables; missing stored history yields unavailable metrics.

## Implemented contracts

### M38: fictional research terminal

Go exposes GET `/history?symbol=ALPHA&from=2026-01-01&to=2026-04-01`. Dates are completed UTC days; `to` is exclusive. Earliest date is 2025-01-01; maximum range is 366 days. Only the existing fictional symbol catalog is supported. The response identifies symbol, `source=fictional-history-v1`, `interval=1d`, and ordered OHLCV candles. Versioned seeded generation always iterates from a fixed anchor, so overlapping ranges reproduce the same candles, including open/close continuity and volumes. Volume is fictional units, not exchange volume. It never reads or modifies the mutable live-price map.

The existing M29 `market_price_samples` table is a five-second live intelligence observation buffer, pruned after 24 hours; it has no volume and cannot reproduce daily fixture history. That sampler and its Kafka intelligence pipeline remain unchanged. V21 adds only the isolated `fictional_market_candles` cache. There is no second live tick collector or new background history job.

Spring GET `/api/research/assets/{assetId}/history?from=...&to=...&period=14` validates range and period (2-100), reads the bounded cache, and fills missing fixtures through Go only on demand. The primary key `(asset_id,interval_code,candle_time)` supports ordered bounded range reads and idempotent inserts. OHLC, positive prices, nonnegative volume, UTC midnight and source-version constraints are enforced in SQL. Ingestion validates response identity, count, dates and candle invariants within one transaction; failures roll back. Existing data is never overwritten.

The response contains identity/provenance, expected/missing days, warnings, bars with indicators, selected-period first/last/change/percentage summary and methodology. Partial history remains partial; no missing candles are invented. Indicator warm-up restarts after gaps. Cached reads work while Go is unavailable. Missing uncached history returns warnings/empty or partial bars rather than invented values.

Definitions: SMA is the arithmetic mean of n closes. EMA starts at the n-close SMA, then alpha=2/(n+1). RSI uses Wilder's average gains/losses over n changes and smoothing thereafter (flat=50, gains-only=100, losses-only=0). Realized volatility is sample standard deviation of n daily log returns, annualized by sqrt(365), expressed as percent. The fictional market has continuous daily observations, so 252 exchange trading days would be inappropriate. Daily change uses the previous available contiguous close; the selected-period summary compares first and last returned closes. Indicators are descriptive, not guaranteed signals.

`/research` uses the current AppShell, Recharts and asset catalog, with candlestick/line modes, SMA/EMA overlays, OHLC hover details, volume, preset/custom ranges, period controls and loading/error/empty states. Asset links from Markets and Risk Lab preserve the selected asset. Replay starts, pauses, resumes and resets a local visible prefix; indicators are causal and the displayed bar never uses later returns. Timers and fetches clean up on range changes/unmount. Replay sends no trading or price-mutation request. Reset returns to the full selected history.

### M39: portfolio Risk Lab

Spring GET `/api/portfolios/1/risk-lab` returns current exposure with a zero-shock scenario. POST `/api/portfolios/1/risk-lab/scenario` accepts:

```json
{"broadShockPct":-10,"assetShocks":{"5":20}}
```

The asset-specific shock **replaces** the broad shock for that held asset. Bounds are -100% to +100%, at most four decimal places. Unknown/unheld assets and invalid values are rejected. Sectors are explicitly unsupported because the actual catalog has no sector classifications. New private analytics endpoints are restricted to local demo portfolio 1; another ID returns 404. This follows the existing fixed demo/SSE boundary and does not add production authentication.

The service reuses PortfolioRepository, PortfolioQueryService holdings/FX/historical portfolio-currency cost, and MarketService. Valuation uses quantity x a validated recent simulated quote x existing reference FX, rounded to four portfolio-currency decimals. Catalog prices are never substituted for missing current quotes. Missing prices make aggregate valuation/scenario results unavailable, while usable per-position data remains visible. Reference FX failures retain the existing service's explicit unavailable behavior. Cash is unchanged by shocks. Unrealized gain/loss uses stored historical portfolio-currency cost.

Results include cash/asset allocations, largest position as a share of total equity, asset-only HHI, effective positions=1/HHI, position-level impact and before/after totals. The UI formats server results rather than calculating separate financial answers. Empty portfolios and zero denominators are explicit; percentages with zero denominators are null.

Historical risk uses the last 90 completed UTC daily candles, static **current** quantities and cash, and aligned daily returns. It is a retrospective what-if basket, not actual portfolio performance. Sample log-return volatility and maximum peak-to-trough drawdown use that basket. Pair correlations use 89 aligned log returns; constant/insufficient series are null. History metrics are bounded to 25 positions; exposure/scenarios to 100. Multi-currency historical metrics are withheld because historical FX is not available. No metric is inferred from insufficient data. Open each held asset's 90-day Research view to populate its fixture cache before calculating historical basket metrics.

Scenario transactions are read-only with REPEATABLE_READ for a consistent portfolio/history snapshot. They never call ingestion, settlement, risk-policy writes, reservations or order APIs. Integration tests fingerprint portfolios, holdings, orders, transactions, receipts, fills and candle history around scenario evaluation.

`/portfolio/risk` is discoverable through portfolio navigation and the existing portfolio page. It shows allocation, broad rise/decline presets, custom and single-asset shocks, current/hypothetical values, position impacts, concentration, historical metrics, correlations and visible assumptions. Editing controls requires Run to update the displayed last-calculated scenario.

### M40: existing Ask AI and MCP

The sibling service extends its existing MCP server, MCP client and `/api/portfolio/chat`; no second chat UI or LLM business calculations were added. Existing order intelligence remains first in routing. EXPIRED order evidence is now accepted and explained without discarding earlier fills.

| Read tool | Arguments | Authoritative backend |
| --- | --- | --- |
| get_fictional_history | assetId, from, to, period=14 | Research history API, at most 366 bars |
| get_technical_summary | same | Same API, last indicator bar plus backend period summary/provenance |
| get_research_context | same | Same bounded summary and methodology |
| get_portfolio_exposure | portfolioId=1 | GET Risk Lab |
| simulate_portfolio_risk | portfolioId=1, broadShockPct, assetShocks? | POST read-only scenario |

Tool schemas reject invalid inputs and private portfolio overrides. Adapters validate response identity, scope, date/period and scenario matches; error bodies never enter explanations. History tools may populate only the isolated fixture cache, not financial state. All money/indicator/scenario arithmetic is owned by Spring. Answers format validated values and identify missing history or unavailable evidence. No new numerical question depends on a live Ollama response.

Optional chat `researchContext` contains `{assetId?,from?,to?,period?,scenario?}`. The existing floating Ask AI receives the explicit current research/scenario context through a small client subscription, with a visible opt-out checkbox. Leaving those views clears the context. Asset questions without selection ask the user to select an asset/period; scenario questions without context or a specified percentage ask for a scenario. No arbitrary asset or scenario is assumed. Examples include moving averages/volatility, selected-period performance, concentration and market falls/rises by a specified percentage. The new private tools remain fixed to demo portfolio 1. Existing holdings and order paths retain their previous behavior.

## Remaining limits and recommended commits

Daily fixture history only; no intraday candles, real securities, sector metadata, historical FX, replay paper-order execution or forecasts. The fixture path is deliberately different from sampled live ticks and is labeled throughout. Historical portfolio metrics model static current holdings, not actual trade-timed performance. Pairwise metrics require complete 90-day aligned fixtures and at most 25 holdings; constant series have no defined correlation. Risk private APIs/tools are restricted to demo portfolio 1 because the repository has no authenticated portfolio ownership layer. Cache retention is on-demand from the fixed 2025 anchor, with no background pruning job. Copilot uses a bounded English intent router; unsupported general questions retain the existing educational assistant path. No visual or running-system integration claim is made.

Recommended main commit: `feat(research): add fictional history terminal and read-only portfolio risk lab`

Recommended AI commit: `feat(ai): add grounded MCP research and risk copilot`

No commit or push was performed.

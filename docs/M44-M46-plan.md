# M44–M46 implementation plan (architecture audit)

Before implementation: transactions contain settled BUY/SELL cash amounts and execution FX, ordered by created_at/id. OMS execution receipts reference those same transactions; replaying both would double count partial fills. Settlement is immediate in OrderService; cancellations and reservations do not change equity. Holdings persist remaining weighted-average historical cost, rounded to four decimals after partial sales. Dividends have a separate persisted payment ledger. There is no contribution/withdrawal ledger or historical FX series. Generated fictional_market_candles are research fixtures, never portfolio price evidence.

Existing portfolio_snapshots contain observed aggregate cash/market values, but no position prices and are captured without a consistent portfolio lock. Old snapshots can support an observational chart, not verified period attribution. Current portfolio UI uses simulated/reference prices; new calculations must require valid recent simulator quotes rather than silently falling back. Backend tests use JUnit/Mockito and optional PostgreSQL Spring integration; frontend uses Node test runner and TypeScript.

1. Extend the existing recorder (no new job) with coherent locked observations and position details. Never backfill missing price history. Bound historical reads to 366 days, one observed endpoint per UTC date, plus period endpoints.
2. Replay settled transactions once with the existing weighted-average rounding. Reconcile replay against persisted holdings. Calculate current lifetime realized/unrealized P&L; period contribution requires verified position observations at both endpoints. Reconcile cash changes against trades and recorded dividends before exposing a no-external-flow return. Otherwise return null and reasons. Never infer an initial cash deposit from today's balance.
3. Implement a read-only planner using OMS quote/FX, availability and risk services. Whole shares, stable asset order, constrained sales then buys, conservative 5% cash reserve buffer matching OMS. Actual settlement credits sale proceeds immediately, but buys in this plan use only existing buying power so each proposed ticket is independently fundable. Show achievable allocations and residual cash.
4. Integrate all three capabilities on Portfolio with shared period selection, small chart, accounting explanations, editable targets, and explicit unavailable/error states. Add focused financial tests, regression checks and final methodology/API/verification documentation.
